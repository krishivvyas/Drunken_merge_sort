Drunken Merge Sort

Every element starts as its own block. Each step the blocks stumble into a random new arrangement; any two neighbours that happen to land in order fuse permanently, and a lone element that falls inside a block's range gets absorbed. Repeat until one block remains. It is a joke name for a real construction — and an honestly terrible sorting algorithm.

Why it usually passes out. Fusions are permanent and greedy, so a run can build two blocks whose ranges nest — say [1,10] and [4,6]. Neither order satisfies max(A) ≤ min(B), and neither is a lone element, so absorption cannot apply either. The run is wedged: no future shuffle can ever help. Past n = 10 that is the overwhelmingly likely ending. Coffee mode unsticks it by allowing one interleave merge — which is exactly natural merge sort's merge step, i.e. the sober algorithm hiding underneath this whole thing.
